# تقرير المرحلة 18: قيد إقفال السنة الآلي

**المرجع:** [ADR-033](../decisions/ADR-033-phase18-year-end-closing.md) و[BUILD_PLAN.md](../BUILD_PLAN.md) §17.
**التاريخ:** 2026-11-19

## 1. ما تم إنجازه مقابل المخرجات (§17)

- معاينة إقفال السنة تعرض السطور والنتيجة الصافية والمسودات والتحذيرات.
- الإقفال يقفل الشركة ثم السنة ثم الفترات، ويتحقق من السنوات السابقة والإقفال النشط والمسودات، ثم يحسب
  الإيرادات والمصروفات لكل (حساب، مركز كلفة، فرع). يرحّل القيد عبر `PostingService`، ويسجل الإقفال ويغلق
  الفترات في معاملة واحدة.
- قيد الإقفال بتاريخ آخر يوم، بفرع رئيسي فارغ، وعلامة `is_closing` ومصدر `YEAR_CLOSING` ورقم `CL` لكل سنة.
  السنوات بلا أرصدة تُسجل كسنوات مقفلة دون قيد.
- إعادة الفتح للمالك فقط؛ تعكس القيد داخل المعاملة، وتفتح الفترة الأخيرة قبل العكس ثم بقية الفترات، وترفض
  إعادة فتح سنة تسبق سنة لاحقة مقفلة.
- قائمة الدخل والدخل حسب مركز الكلفة يستثنيان قيود الإقفال وعكسها. ميزان المراجعة يستثنيها افتراضياً ويوفر
  `afterClosing`، بينما الميزانية وكشف الحساب والأستاذ العام تضمها. لوحة البداية تقرأ ملخصات المستندات لا
  القيود، ولذلك لا تعرض قيد الإقفال.
- أضيفت معاينة الإقفال في صفحة السنوات، وإعادة الفتح للمالك فقط، وخيار ميزان ما بعد الإقفال، وتسميات الإقفال
  في الأستاذ/الكشوف عبر i18n.
- فحص السلامة و`ledger:check` يقبلان المصدر `YEAR_CLOSING`.

## 2. الجداول والـ migrations

`20261119210617_phase18_year_closing`:
- إضافة `journal_entries.is_closing` وفهرس الشركة/التاريخ/العلامة.
- إنشاء `fiscal_year_closings` للحالة والنتيجة والقيد الأصلي وقيد العكس ومن أغلق/أعاد الفتح ومتى، مع علاقات
  tenant-aware.
- إنشاء تسلسل `YEAR_CLOSING` بالبادئة `CL` لكل سنة مالية قائمة.

## 3. الـ endpoints والشاشات

- `GET /api/v1/fiscal-years/:id/closing-preview`.
- `POST /api/v1/fiscal-years/:id/close` و`POST /api/v1/fiscal-years/:id/open`، مع `Idempotency-Key`.
- شاشة السنوات المالية: معاينة السطور والنتيجة والمسودات والتحذيرات، وإظهار إعادة الفتح للمالك فقط.
- شاشة التقارير: خيار «بعد الإقفال» لميزان المراجعة، وتسمية قيود الإقفال في كشوف الحساب والأستاذ العام.
