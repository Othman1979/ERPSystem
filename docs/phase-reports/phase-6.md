# تقرير المرحلة 6 — الخزينة

**التاريخ:** 2026-11-09
**الفرع:** `phase-6-treasury` (فوق `phase-5-gaps` ← `ui/batch-1-fixes`)
**الحالة:** منجزة ومختبرة؛ migration المرحلة طُبقت على `erp_dev` بعد موافقة المالك (2026-11-09) والشاشات متحقق منها في المتصفح.

## 1. ما تم إنجازه مقابل المخرجات

| المخرَج | الحالة |
|---|---|
| cash_boxes، bank_accounts | ✅ (من المرحلة 5) + تقرير أرصدة |
| receipts، payments (لطرف أو مصروف) | ✅ (من المرحلة 5) + فرع + عكس |
| cash_transfers | ✅ جديد — إنشاء وترحيل وعكس |
| allocations | ✅ يدوي عند الإنشاء أو لاحقاً، وإلغاء مع حفظ التاريخ |
| التخصيص التلقائي على أقدم فاتورة (اختياري) | ✅ عند الإنشاء أو لاحقاً |
| تقرير أعمار الديون | ✅ للعملاء والموردين |
| الشاشات | ✅ الخزينة: تبويبا التحويلات والأرصدة، عكس السندات وإلغاء التخصيص وتخصيص المتبقي؛ التقارير: تبويب أعمار الديون |

ملاحظة: الصناديق والبنوك والسندات والتخصيص بُنيت مبكراً في المرحلة 5؛ هذه المرحلة أكملت الباقي
وأغلقت ثغرات فيها (انظر 6).

## 2. الجداول والـ migrations
- `20261109200835_phase6_treasury` (إضافية فقط):
  - جدول `cash_transfers` (مفاتيح مركبة `[tenant_id, id]`، `UNIQUE(tenant_id, transfer_no)`).
  - `receipts`/`payments`: `branch_id`، `reversed_at`، `reversed_by`، `reversal_entry_id`.
  - `allocations`: `created_by`، `cancelled_at`، `cancelled_by`.
- `CashTransfer` مضاف إلى `TENANT_MODELS` (عزل تلقائي).
- طُبقت على `erp_test` ثم على `erp_dev` بعد موافقة المالك؛ الصفوف القائمة لم تتغير.

## 3. الـ endpoints والشاشات
| الطريقة | المسار | الوظيفة |
|---|---|---|
| GET/POST | `/cash-transfers`، GET `/cash-transfers/:id` | التحويلات النقدية |
| POST | `/cash-transfers/:id/reverse` | عكس تحويل |
| POST | `/receipts/:id/reverse`، `/payments/:id/reverse` | عكس سند (يُرفض إن كان عليه تخصيص) |
| POST | `/receipts/:id/allocations`، `/payments/:id/allocations` | تخصيص المتبقي يدوياً أو `auto` |
| POST | `/allocations/:id/cancel` | إلغاء تخصيص |
| GET | `/reports/aging?partyType=CUSTOMER\|SUPPLIER` | أعمار الديون |
| GET | `/treasury/balances` | أرصدة الصناديق والبنوك |

حقول جديدة في الاستجابات: الفواتير `creditedAmount` و`outstanding`؛ السندات `allocatedAmount`
و`unallocatedAmount` و`reversedAt`. `autoAllocate` في إنشاء السندات.

الشاشات: الخزينة (تحويلات، أرصدة، عرض السند مع العكس وإلغاء التخصيص وتخصيص المتبقي، خيار التخصيص
التلقائي في نافذة السند)، التقارير (أعمار الديون؛ ميزان المراجعة يحترم فلتر التاريخ؛ اختيار الطرف من
قائمة بدل كتابة رقمه)، القيود (زر العكس يختفي عن قيود المستندات). `packages/api-client` أُعيد توليده.

**ما زال مفتوحاً (لم يُطلب في هذه الجولة):**
- قيود مرتجعات البيع والشراء والتسويات المخزنية لا تحمل فرعاً (ADR-003 §3 يقول إن المرتجع يتبع فرع فاتورته).
- القيد اليدوي يأخذ فرعه من جسم الطلب، بخلاف ADR-003 §2.
- الخزينة ما زالت تقرأ `parties` و`accounts` مباشرة في التحقق من السند، و`journal_lines` في أرصدة الصناديق.
- الفاتورة النقدية تعرض `outstanding = grand_total` في الـ API لأن `paid_amount` لا يُضبط عند ترحيلها.
- الـ CI لا يبني الـ API ولا يطبّق الـ migrations ولا يزرع البيانات قبل اختبارات e2e، مع أنها تشغّل `dist/main.js`.
- أعمار القيود الافتتاحية من تاريخ بدء العمل لا من تاريخ الفاتورة الأصلية (يحتاج مستندات افتتاحية — المرحلة 10).
