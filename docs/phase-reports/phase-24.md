# تقرير المرحلة 24: تعديل القيود والسندات المرحّلة قبل إقفال السنة

**المرجع:** [ADR-039](../decisions/ADR-039-phase24-posted-edit.md) و[BUILD_PLAN.md](../BUILD_PLAN.md) §17.
**التاريخ:** 2026-11-20

## 1. ما تم إنجازه

- تعديل مباشر للقيد اليدوي المرحّل: التاريخ والبيان والأسطر، بالرقم نفسه (`PostingService.amendEntry`).
- تعديل مباشر لسند القبض والصرف المرحّل: التاريخ والمبلغ والصندوق أو البنك وحساب المصروف ومركز التكلفة والمرجع والبيان.
  الشيك المرتبط يأخذ المبلغ والتاريخ الجديدين.
- الرفض: فترة مقفلة (القديمة أو الجديدة)، قيد معكوس أو عكسي أو إقفال، قيد مولّد من مستند، سطر مطابق بنكياً،
  سند مخصص على فواتير، شيك تحرّك بعد الاستلام أو الإصدار.
- سجل تدقيق قبل/بعد لكل تعديل (`journal.amend`، `receipt.amend`، `payment.amend`).
- الواجهة: زر "تعديل" على القيد اليدوي المرحّل (يفتح نموذج القيد بقيمه)، وعلى السند المرحّل غير المخصص (نافذة تعديل).

## 2. الجداول والـ migrations

لا migration. التعديل يستبدل صفوف `journal_lines` ويحدّث `journal_entries` و`receipts`/`payments` و`cheques`.

## 3. الـ endpoints

`POST /journal-entries/:id/amend` (`journal.post`)، `POST /receipts/:id/amend` و`POST /payments/:id/amend` (`treasury.manage`).
كلها تتطلب `Idempotency-Key`.

## 4. الاختبارات

- `test/e2e/golden-posted-edit.e2e.spec.ts`: E1–E3 وعزل المستأجر B (10 اختبارات).
- `test/e2e/isolation-sweep.e2e.spec.ts`: مسارات `amend` الثلاثة.
- `pnpm typecheck` و`pnpm lint` للـ API والويب.

## 5. مستثنى

تعديل فواتير البيع والشراء المرحّلة مستثنى بقرار المالك (2026-11-20). تُصحَّح الفاتورة المرحّلة بالمرتجع أو بالإشعار الدائن كما هو الآن.

## 6. يحتاج اعتماد المحاسب

أرقام E1–E2 في §18.
