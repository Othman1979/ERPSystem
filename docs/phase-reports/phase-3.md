# تقرير المرحلة 3 — محرك القيود والتقارير المحاسبية

**التاريخ:** 2026-11-07
**الحالة:** مكتملة ومتحقق منها

## النطاق المنجز

### قاعدة البيانات
- جداول جديدة (tenant-scoped، مفاتيح مركبة):
  - `journal_entries` — رقم قيد متسلسل (`entry_no`)، تاريخ، حالة `DRAFT|POSTED`، إجمالي مدين/دائن، ربط عكسي (`reversal_of_id`)
  - `journal_lines` — سطور القيد: حساب، مدين/دائن (Decimal)، طرف اختياري (`party_type`/`party_id`)، فرع، وصف
  - enum `JournalEntryStatus`
- كل النماذج أُضيفت إلى `TENANT_MODELS` فتُطبَّق عليها عزل المستأجر تلقائياً.

### محرك الترحيل (`posting.service.ts`)
- `validateLines` — يتحقق من: حساب موجود وفعّال وقابل للترحيل (`is_postable`)، ليس حساباً أب غير قابل للترحيل، ليس حساب رقابة بدون طرف، مدين/دائن غير سالب وغير صفري معاً.
- `totals` — جمع Decimal دقيق للسطرين.
- `resolveOpenPeriod` — إيجاد الفترة المالية المفتوحة المطابقة لتاريخ القيد؛ يرفض التواريخ خارج أي سنة مالية.
- ترقيم القيود عبر `document_sequences` (`JV-YYYY-…`) داخل معاملة `SELECT … FOR UPDATE` لضمان عدم التكرار.

### خدمة القيود (`journal.service.ts`)
- `POST /journal-entries` — إنشاء مسودة (لا ترحيل فوري).
- `POST /journal-entries/:id/post` — ترحيل المسودة: تحقق من التوازن، الفترة المفتوحة، ثم قلب الحالة إلى `POSTED` وترقيمها — كلها في معاملة واحدة.
- `DELETE /journal-entries/:id` — حذف المسودات فقط.
- `POST /journal-entries/:id/reverse` — إنشاء قيد عكسي `POSTED` مع تبديل مدين/دائن وربط `reversal_of`؛ القيد الأصلي لا يُحذف.
- `POST /journal-entries/opening` — قيد أرصدة افتتاحية: يحسب الفرق ويقيده تلقائياً في حساب `OPENING_BALANCE_EQUITY` عبر الـ mapping.

### التقارير (`reports.service.ts`)
- `GET /reports/trial-balance` — ميزان مراجعة مجمّع على القيود المرحّلة.
- `GET /reports/general-ledger?accountId&from&to` — دفتر أستاذ مع رصيد تراكمي.
- `GET /reports/party-statement?accountId&partyType&partyId&from&to` — كشف حساب طرف (عميل/مورد) على الحسابات الرقابية.

### الواجهة
- `JournalPage` — قائمة القيود (فلتر بالحالة)، إنشاء قيد مسودة بأسطر ديناميكية، ترحيل/حذف/عكس، وعارض تفاصيل.
- `ReportsPage` — تبويبات: ميزان المراجعة، دفتر الأستاذ (برصيد تراكمي)، كشف حساب طرف؛ فلاتر تاريخ/حساب/طرف.
- مفاتيح ترجمة عربية/إنجليزية كاملة.

## الأخطاء المُصلحة أثناء العمل
- **خلل في `fiscal.service.ts`:** كائن `Date` واحد قابل للتغيير كان يُخزَّن في كل الفترات فأصبحت كل `startDate` تساوي التاريخ النهائي. أُصلح بنسخ التاريخ (`new Date(pStart)`).
- **توقعات اختبارات:** رموز أخطاء `PERIOD_CLOSED`/`UNBALANCED_ENTRY` تُرجع 409/400 حسب خريطة `DomainError` — حُدّثت الاختبارات.
- **Jest:** تشغيل `maxWorkers: 1` لأن كل جناح e2e يشغّل عملية API كاملة + اتصال DB (توازي يتجاوز موارد الجهاز).
