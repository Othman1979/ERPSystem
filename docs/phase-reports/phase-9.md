# تقرير المرحلة 9 — الجاهزية التجارية

**التاريخ:** 2026-11-11
**الفرع:** `phase-9-saas` (فوق `feat/report-opening-columns` ← `feat/opening-balances`)
**الحالة:** منجزة ومختبرة، ما عدا الاستيراد من Excel، فقد **أجّله المالك**. migrations المرحلة طُبقت على
`erp_test` و`erp_dev`، وأُخذت نسخة احتياطية من `erp_dev` قبلها. القرارات في
[ADR-009](../decisions/ADR-009-phase9-saas.md).

## 3. الـ endpoints والشاشات
| الطريقة | المسار | الوظيفة |
|---|---|---|
| GET، PATCH | `/admin/plans`، `/admin/plans/:code` | الباقات (مدير المنصة) |
| POST | `/admin/tenants/:id/subscriptions` | صار يقبل `amount` (تسجيل دفعة) |
| GET، PATCH | `/company` | بيانات الشركة |
| GET، POST، DELETE | `/company/logo` | الشعار: base64، رفع multipart، حذف |
| POST | `/company/onboarding/complete` | إكمال معالج الإعداد |
| GET | `/export/tenant-data` | تصدير بيانات الشركة (ZIP) |

**سلوك جديد:** ترحيل فاتورة بيع تتجاوز حد الباقة الشهري يُرفض بخطأ 402 `PLAN_LIMIT_EXCEEDED`.

**الشاشات:**
- `/platform`: إدارة المنصة، لمدير المنصة فقط.
- `/setup`: معالج الإعداد.
- الإعدادات: تبويبا «بيانات الشركة» و«تصدير البيانات».
- `/help`: المساعدة، ويُفتح من زر «؟» في الشريط العلوي.
- `/privacy` و`/terms`: متاحتان للزائر أيضاً، وصفحة التسجيل ترتبط بهما.

**إصلاحات:**
- `PrismaService` يغلق اتصالات MariaDB عند الإيقاف، فالأوامر ذات التشغيل الواحد تنتهي.
- `api-client` لم يعد يفرض نوع المحتوى JSON على رفع الملفات (FormData).

## 4. نتائج اختبارات القبول
| البند (§17) | الحالة |
|---|---|
| مستخدم جديد يكمل الإعداد ويصدر أول فاتورة دون مساعدة (مع شخص حقيقي) | ⏳ **يختبره المالك**. المعالج والتنبيه جاهزان |
| استيراد ملف فيه أخطاء يعرضها كلها ولا يحفظ شيئاً | ⏸ لا ينطبق: الاستيراد مؤجَّل |
| الأرصدة الافتتاحية المستوردة تنتج ميزاناً متوازناً | ⏸ لا ينطبق. **الإدخال اليدوي** للأرصدة الافتتاحية يُنتج ميزاناً متوازناً، ويغطيه `opening-balances.e2e` |
| التصدير يعمل في حالة SUSPENDED | ✅ `phase9-export.e2e`، في حالتي SUSPENDED وCANCELLED |
| انتهاء الفترة التجريبية ينقل الحالة وفق §13.2 | ✅ `phase9-saas.e2e`: التجربة، الاشتراك المنتهي، فترة السماح، الاحتفاظ بعد الإلغاء، والتشغيل الثاني لا يغيّر شيئاً |

**اختبارات المرحلة الجديدة:**
- `phase9-saas.e2e` (10): الحالات، حد الفواتير، الباقات، الدفعات، القراءة فقط.
- `phase9-company.e2e` (8): بيانات الشركة، الشعار ونوعه وحجمه، ظهوره في PDF، العزل.
- `phase9-export.e2e` (7): المحتوى والمبالغ الدقيقة، غياب الأسرار، المالك فقط، الحالات المعلّقة، العزل.
- `phase9-purge.e2e` (5): الرفض في كل حالة غير مسموحة، المعاينة لا تغيّر شيئاً، لا يبقى صف للمستأجر في أي
  جدول، حذف الملفات والمستخدمين المنفردين، بقاء المستخدم المشترك، والمستأجر الآخر كما هو (صفوفه وميزانه).
- `einvoice.e2e` (+1): أمر Cron يرسل الطابور، وأمران متزامنان لا يرسلان مستنداً مرتين.
- الويب: `helpTexts.spec.ts` يتحقق أن لكل قسم نصاً بالعربية والإنجليزية.

**المجموع:**
- `pnpm test`: الـ API 30 ملفاً، 276 اختباراً ناجحاً و5 متجاوزة. الويب 11 ملفاً، 48 اختباراً.
- `pnpm typecheck` و`pnpm lint` نظيفان.
- تحقق في المتصفح: إدارة المنصة (بصلاحية مؤقتة أُعيدت كما كانت)، المعالج، بيانات الشركة، التصدير،
  المساعدة، الخصوصية.

## 5. أوامر التشغيل والنشر
- **Cron**، بعد `pnpm --filter api build`. كل أمر يطبع ملخصاً بصيغة JSON، ويخرج برمز 1 عند الخطأ:
  ```
  30 0 * * * cd /path/apps/api && node dist/jobs/cli.js tenant-status >> logs/jobs.log 2>&1
  * * * * *  cd /path/apps/api && node dist/jobs/cli.js einvoice-send  >> logs/jobs.log 2>&1
  ```
- **`EINVOICE_WORKER` صار افتراضياً `off`.** في الإنتاج الإرسال بالأمر أعلاه. في التطوير: شغّل الأمر، أو
  اضبط `EINVOICE_WORKER=on` في `.env`.
- **حذف مستأجر ملغى بعد الاحتفاظ** (يدوي فقط):
  - `node dist/jobs/cli.js purge-tenant <id>` يعرض المعاينة فقط.
  - مع `--confirm "<الاسم الكامل>"` يحذف فعلاً.
  - المهمة اليومية تعرض في `dueForDeletion` من حان حذفه.
- **متغيرات بيئة جديدة**، موجودة في `.env.example` وفي schema التحقق:
  `TRIAL_DAYS=14`، `GRACE_DAYS=7`، `RETENTION_DAYS=90`، `STORAGE_DIR=storage`.
- **`STORAGE_DIR`** خارج مجلد الموقع، ويجب أن يدخل في **النسخ الاحتياطي اليومي** مع قاعدة البيانات
  (§14-10).
- **النشر:** `pnpm --filter api prisma migrate deploy` ثم إعادة تشغيل الـ API.
- **مكتبة جديدة:** `fflate` 0.8.2، بإصدار مثبّت.

## 6. المشاكل المعروفة والديون التقنية
- **الاستيراد من Excel مؤجَّل.** البدائل اليوم: شاشة الأرصدة الافتتاحية، والتسويات الافتتاحية، والإدخال
  من الشاشات.
- ~~حذف البيانات بعد الاحتفاظ: الأمر لم يُبنَ.~~ أُغلق: `purge-tenant` (ADR-009 §14)، واختباره
  `phase9-purge.e2e`.
- ~~عامل الفوترة الإلكترونية يعمل داخل الخادم.~~ أُغلق: `einvoice-send` بأمر Cron (ADR-009 §15)، واختبار
  الأمرين المتزامنين في `einvoice.e2e`.
- **التصدير يُبنى في الذاكرة.** هذا كافٍ للشركات الصغيرة، ويلزم البناء المتدفق للأحجام الكبيرة.
- **حد الفواتير الشهري:** فاتورتان تُرحّلان في اللحظة نفسها عند الحد قد تمران معاً. هذا مقبول لحد
  تجاري، ومذكور في الكود.
- **نصوص الخصوصية والشروط مسودة**، وفيها حقول تنتظر الاستكمال: بيانات التواصل، وصياغة حدود المسؤولية.
- **الشعار** يظهر في PDF فقط، لا في ملفات Excel المصدّرة.
- **صفحتا الخصوصية والشروط للزائر:** تعملان في الكود، لكن لم أجرّبهما في المتصفح لزائر غير مسجّل.
- **حساب العرض** في `erp_dev` بلا صندوق رئيسي. المعالج يعرض إنشاءه، ولم يُنشأ حتى لا تتغير البيانات.
- **اختبار «العاملين المتزامنين» في `einvoice`** قد يتجاوز المهلة في التشغيل الكامل. الإصلاح في PR #8.
