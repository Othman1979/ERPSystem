# تقرير المرحلة 10: التجربة والإطلاق

**التاريخ:** 2026-11-13 (الجزء التقني)، 2026-11-15 (الإغلاق)
**الحالة:** **أُغلقت المرحلة بقرار المالك في 2026-11-15، مع بنود مفتوحة.**
- **الجزء التقني (10.1–10.5):** منجز ومراجَع ومختبر.
- **برنامج المراجعة والإصلاح:** منجز. مراجعة شاملة للنظام في 2026-11-13، أُصلحت كل بنودها في #19–#41.
- **التجربة مع الشركات والمحاسب (10.6):** لم تبدأ. تُحمل بنوداً مفتوحة (القسم 8)، وتسير بالتوازي مع المرحلة
  11 لأنها لا تنتظرها (ADR-013، والقاعدة في §17).
- **القرارات:** [ADR-010](../decisions/ADR-010-phase10-launch.md) للجزء التقني، والقرارات من ADR-012 إلى ADR-023
  للمراجعة (القسم 7).
- **المراجعة:** كل طلب مرّ بمراجعة مستقلة، وأُصلحت ملاحظاته وتُحقق منها قبل الدمج.

## 3. الـ endpoints والشاشات
- **من الجزء التقني:** `POST /client-errors`، و`/admin/errors…`، وتبويب «الأخطاء».
- **من المراجعة، تغييرات في العقد:**
  - كل القوائم تعيد `{ items, page, pageSize, total }`، والكشوف تقرأ بمؤشر (ADR-022).

  - قبول الدعوة برمز.
  - `GET /stock/balances?itemIds=` لأصناف الصفحة.

- **الشاشات:**
  - أزرار الصفحات في كل القوائم.
  - إخفاء ما لا يملكه المستخدم.
  - شاشة «تعذر الاتصال».
  - رموز «الحبر».

- **CI على GitHub متوقف** بقرار المالك، ولا يُستخدم إلا بطلبه.
- **بوابة الدمج:** مراجعة مستقلة، ثم اختبارات الملفات المتأثرة محلياً، ثم الدمج حين يكون آمناً.
- **قاعدة الاختبار:** `erp_test` أُعيد بناؤها فارغة في 2026-11-14. ويمكن استعمال قاعدة خاصة بـ `E2E_DB_NAME`،
  واسمها يجب أن يحوي `test` (`docs/runbooks/testing.md`).

## 5. أوامر التشغيل والنشر الجديدة
- **Cron:**
  - `backup` يومياً.
  - `error-digest` كل ساعة.
  - `purge-expired` يومياً (مفاتيح Idempotency ورموز refresh المنتهية).
  - `stock-verify` يومياً.
  - مع `tenant-status` و`einvoice-send`.
- **يدوي:**
  - `preflight` قبل النشر وبعده.
  - `backup-verify latest` شهرياً.
  - `backup-decrypt` عند الاستعادة اليدوية.
  - `integrity-check` شهرياً وبعد كل استعادة.
  - `ledger:check` قبل `migrate deploy`.
  - `reset-password <email>`.
  - `grant-platform-admin <email>`.
- **محلياً:**
  - `start-local.bat` للتشغيل بنقرة.
  - `pnpm --filter api db:create`.
  - `pnpm --filter api start:web` على المنفذ 3002.
- **الأوامر كلها** في `CLAUDE.md`، والمتغيرات في `.env.example` وschema التحقق.

## 6. المشاكل المعروفة والديون التقنية
- **التحقق من البريد** للدعوات، **واستعادة كلمة المرور بالبريد:** مؤجلان حتى يُختار مزود بريد. رمز القبول
  (ADR-012) يغطي خطر الدعوة مؤقتاً.
- **أعمار الذمم المقيّدة بفرع:** تقرأ كل تخصيصات الشركة حتى تاريخ التقرير، نحو 440 مللي ثانية على 60 ألف تخصيص.
  الحل المحدود يحتاج migration وقرار المالك إن ظهر بطء (ADR-003 §21).
- **فرق السعر بين الفاتورة والاستلام:** ADR-013 §4 يتعارض مع ADR-016 §2 المطبّق. يحسمه المحاسب قبل المرحلة 13.
- **النسخ خارج الخادم يدوي أسبوعي** (ADR-010 §4).
- **حدود الطلبات في ذاكرة كل نسخة** (ADR-011): تكفي نسخة واحدة.
- **التحديث يحتاج نافذة صيانة**، خصوصاً migrations الجداول الكبيرة (القسم 2).
- **`erp_dev` فيه شركات اختبار** أنشأتها جلسات المراجعة. حُذفت منها الشركة 13 (اختبار عكس القيد مرتين) لأنها
  منعت الـ migrations. البقية لا تمنع شيئاً، وتُحذف متى شاء المالك.
